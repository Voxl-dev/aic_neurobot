Pipeline de entrenamiento por capas

CAPA 0
Keypoint Pose Estimator
Entrada: Dataset A (15k imgs)  ·  Modelo: MobileNetV3-Small  ·  Salida: pose_relativa [6D]
Cmd: pixi run python scripts/train_keypoint_estimator.py --connector_type sfp
↓ la salida de Capa 0 se agrega al vector de estado → 32D
CAPA 2
ACT Policy — ResNet-18 + Transformer
Entrada: B (70%) + C (30%)  ·  Estado: [32D]  ·  chunk_size: 20  ·  Salida: Twist [6D]
Cmd: pixi run lerobot-train --policy.type=act --policy.chunk_size=20
↓ se activa solo cuando dist_plug_tip ≤ 5 mm
CAPA 3
SAC Residual — MLP 256×256
Entrada: Dataset D (80k trans.)  ·  Estado: [32D]  ·  Salida: Δaction [3D]
Requiere: AIC_ENABLE_ACL desactivado durante entrenamiento (reward desde /scoring/insertion_event)
↓ todas las capas bajo supervisión de
FSM
Safety Monitor — 50 Hz
F/T > 20 N por >1s → RETRACT  ·  Reintentos ≤ 3  ·  Timeout: 160 s (de 180 s max)
Evita penalización: −12 pts (force) y −24 pts (contact)

Advertencias críticas

🚫
/scoring/** bloqueado durante evaluación

El topic /scoring/insertion_event está bloqueado por el ACL de Zenoh para el contenedor model (ver docker/aic_eval/aic_zenoh_config.json5). Solo se puede usar durante entrenamiento local con AIC_ENABLE_ACL desactivado. El SAC entrenado no depende de este topic en inferencia.

⚠️
Cambiar ground_truth antes de subir al portal

El docker-compose.yaml actual tiene ground_truth:=true. Debe cambiarse a ground_truth:=false en la imagen de evaluación oficial. Los frames /tf de puertos NO estarán disponibles en evaluación.

🔧
Tare del sensor F/T

El scoring llama al tare automáticamente antes de spawnear el cable. Durante la grabación de datasets, hacer tare manualmente: ros2 service call /aic_controller/tare_force_torque_sensor std_srvs/srv/Trigger antes de cada episodio.

🌐
Domain gap sim → real (Fase 2)

El Keypoint Estimator entrenado en Gazebo necesitará fine-tuning para el workcell físico. Isaac Lab (aic_utils/aic_isaac/) tiene randomize_dome_light() y randomize_board_and_parts() para mayor variedad de iluminación y posición.

✅
Uso de ground truth en entrenamiento: permitido

Las reglas del reto (challenge_rules.md sec. 2.c) permiten explícitamente usar toda la información de estado interna, incluyendo /tf, durante entrenamiento. El uso de ground_truth:=true para Dataset A y B es válido.
